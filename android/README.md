# 가이아 웰니스 안드로이드 1016-Q

- Android 8 이상. 기기의 세로·가로 회전 설정을 따릅니다. 패키지명과 내부 저장 주소를 유지해 이전 앱 위에 업데이트합니다.
- **설정 → 드라이브 저장 → 새 저장 파일 만들기**에서 Google Drive에 JSON을 한 번 만듭니다. 다른 기기는 **기존 파일 연결**로 그 파일을 선택합니다. 같은 이름의 새 파일을 따로 만들지 않습니다.
- 기기 저장이 우선이며 오프라인 플레이가 가능합니다. 시작·복귀·온라인 복귀·지금 동기화 때 파일을 읽습니다. 두 기기에서 각각 진행했으면 진행 내용을 비교해 선택합니다. Drive 제공자의 업로드 지연까지 실시간으로 보장하지는 않습니다.
- JSON에는 v3 게임 상태, 동기화 버전, 플레이 기록을 함께 담습니다. 기존 단독 v3 JSON도 불러올 수 있습니다. 웹의 수동 파일 내보내기/불러오기도 유지합니다.
- 기록: 실제 조작이 있는 플레이 시간(90초 이상 무조작 제외), 골드 증감, 모집·졸업, 건물별 회원 체류 시간, 일별 진행 요약, 미니게임 결과·팁. 최근 이벤트 200건·날짜 90개로 크기를 제한합니다. 기록은 저장 파일에만 들어가며 별도 분석 서버로 전송하지 않습니다.

## 서버 업데이트
- APK는 시작할 때 GitHub Release `wellness-live/manifest.json`을 확인합니다. 완성된 단일 HTML을 gzip으로 받아 SHA-256을 검증한 후 원자적으로 캐시합니다. 검증 실패·연결 실패 때는 마지막 검증본 또는 APK 내장본을 실행합니다.
- 업데이트가 오래 걸리면 `지금 플레이` 또는 25초 후 기존 게임을 시작합니다. 늦게 받은 업데이트는 다음 실행에 적용하며 플레이 중 새로고침하지 않습니다.
- HTML은 계속 같은 내부 HTTPS 주소에서 실행해 저장 출처가 바뀌지 않습니다. WebView의 외부 탐색·외부 요청은 차단하고, 네이티브에서 정해진 저장소의 업데이트만 다운로드합니다.
- 게임 수정은 main의 자동 빌드가 성공하면 다음 앱 실행 때 반영됩니다. 네이티브 기능·권한·서명 변경에는 새 APK가 필요합니다.

## 빌드·서명
- **APK는 `.github/workflows/build-apk.yml` 자동 빌드만 사용합니다.** 실행 번호로 versionCode를 증가시키며 기존 `ANDROID_KEYSTORE_B64` Secret을 사용합니다. Secret이 없으면 새 키로 바꾸지 않고 중단합니다.
- 키는 git에 올리지 않습니다. 기존 비공개 소스 백업의 `android/keys/gaia-test.jks`를 보관합니다. 비밀번호 android, 별칭 gaia-test. 패키지는 city.gaia.wellness.
- CI에서 저장 분기·JSON 검사를 실행하고, 서명 확인한 APK와 검증용 HTML을 Artifacts에 보관합니다. main 빌드는 APK 및 무결성 검사용 게임 업데이트를 GitHub Release에도 올립니다.
- INTERNET·ACCESS_NETWORK_STATE만 추가했습니다. 넓은 저장소 권한은 없으며 SAF로 선택한 문서만 사용합니다. 진동 권한은 추가하지 않았습니다.

## 검증 범위
- Java 컴파일, baseT 분기·손상 JSON 검사, 웹의 시작/충돌 저장 차단·선택 취소·불러오기·기록 내보내기·기존 네임드/관리 회귀를 검사합니다.
- 실제 Android 문서 제공자, 두 실기기의 Drive 업로드 지연, 실제 설치 및 터치는 케인의 기기 확인이 필요합니다. 웹 브리지 모의 검사를 실기기 검증으로 보고하지 않습니다.
